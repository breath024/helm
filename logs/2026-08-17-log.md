## 터진 것 / 헛짚은 것
**증상.** HELM 안 claude에게 "만든 이미지 열어줘"라고 하면 아무것도 안 뜬다.
같은 말을 HELM 밖에서 하면 뜬다.

**헛짚은 순서 (셋 다 틀림).**
1. NTFS 권한 → 아님. 열려던 게 홈 아래 자기 파일이라 애초에 권한이 있다.
2. `_safe()` 화이트리스트(`app.py:301`) → 아님. 그건 **편집기 패널 전용** 제한이고
   터미널 안 claude에겐 안 걸린다. 게다가 루트에 홈이 들어있어 `C:\Users\USER` 아래는 다 통과.
3. 셸 샌드박스가 GUI 실행을 막는다 → 아님. 실측으로 깨졌다(아래).

**진짜 원인.** `SendUserFile` 도구다. 이건 파일을 **클라이언트에 넘겨 카드로 그리게** 하는
물건인데, HELM 화면은 xterm.js라 그릴 데가 없다. 그런데 도구는 성공을 반환한다 —
`4 files delivered to user`. 그래서 **claude는 보낸 줄 알고, 호윤은 아무것도 못 본다.**
어제(08-16) 세션 `6c3da05b` 18:35 기록에 그대로 남아 있다:

```
[assi|18:35|TOOL:SendUserFile] {"files": [lav_1.png … lav_4.png]}
[user|18:35|res]  4 files delivered to user.
[assi|18:35] 4장 다시 보냈어. 이것도 안 뜨면 탐색기로 직접 열어봐
```

**고친 방법.** 셸로 여는 경로는 멀쩡하므로(실측), `--append-system-prompt`로 세션마다
"SendUserFile 쓰지 말고 `Invoke-Item`으로 띄워라"를 주입한다.

**교훈.** 도구가 성공을 반환한다고 사용자에게 도달한 건 아니다.
HELM은 **CLI를 그대로 그리는 껍데기**라, 클라이언트 렌더링에 의존하는 기능은 조용히 죽는다.

## 확인한 것
- **셸로 파일 열기는 HELM 안에서도 된다** — HELM으로 띄운 세션에서 `Invoke-Item cl.png` 실행 →
  Photos 프로세스 38400번이 07:41:31에 새로 생성됨. 부모 사슬로 HELM 안임을 증명:
  `powershell ← claude.exe ← pythonw.exe(HELM) ← explorer.exe`
- **인자가 안 깨진다** — 안내문에 따옴표·한글이 섞여 있어 PTY 인용에서 깨질 수 있었다.
  winpty로 실제 spawn해 받아 대조: 278자 **완전 일치**.
  (`pywinpty`는 `subprocess.list2cmdline`으로 조립 — `ptyprocess.py:90`)
- **claude가 실제로 받는다** — 그 지침을 붙여 띄우고 "SendUserFile 관련 지침 있냐" 질의 →
  `Invoke-Item로띄우기` 응답. rc 0.
- `python -m py_compile app.py` 통과.
- **안 함**: HELM 창을 새로 띄워 실제 이미지 요청까지 눌러보는 끝단 확인은 호윤 몫으로 남김
  (기존 패널은 이미 뜬 프로세스라 적용 안 됨 — 새 패널부터).
