호윤이 "헬름으로 서버구축 중이었는데 오늘 연속으로 2번이나 작업한 게 날아갔다"고 왔다.
날아간 게 아니라 **HELM 이 세션 목록에서 갈라진 세션을 구분 못 해서 버려진 쪽을 열어준
것**이었다. 원인을 잡고 고쳤다. 겸사겸사 9/15 부터 커밋 없이 쌓여 있던 hcom 작업분도 올렸다.

## 무슨 일이었나

세션이 갈라질 때 CLI 는 옛 파일 끝에 자취를 남긴다.

```json
{"type":"continued-in",
 "sessionId":"e4a1738a-…",
 "continuedInSessionId":"5f58a666-…"}
```

문제는 **갈라진 세션이 앞부분을 통째로 복사해간다**는 것이다. 그래서

| | 원본 | 갈라진 것 |
|---|---|---|
| 제목(첫 사용자 발화) | 같다 | 같다 |
| 프로젝트·cwd | 같다 | 같다 |
| mtime | 비슷하다 (목록에서 나란히 뜬다) | |

목록에 **구분할 방법이 없는 두 줄**이 뜬다. 버려진 쪽을 고르면 그 뒤 작업이
통째로 사라진 것처럼 보인다. 호윤이 본 게 이거다.

실제 사례 — 서버구축 세션:

```
e4a1738a   17:17 → 18:59   버려진 가지 (호윤이 이걸 열었다)
5f58a666   17:17 → 22:25   진짜 이어진 쪽. 클플·DNS·메일·용량정리가 전부 여기
```

이 PC 세션 전수를 훑으니 `continued-in` 이 **8건**, 그중 **7건이 버려진 가지**였다.
어제 킨텍스 세션(`9b091ea1`)도 같은 건이다. "2번 날아갔다"가 이거였다.

## 바꾼 것

| 파일 | 무엇을 |
|---|---|
| `app.py` `_tail_scan()` | `continued-in` 과 그 뒤 대화 수(`after`)를 같이 뽑는다 |
| `app.py` `scan_sessions()` | `after == 0` 인 가지는 목록에서 뺀다. 제목+프로젝트가 겹치면 `branched` |
| `app.py` `_CACHE_VER` | 신설(=2). 캐시 무효화 조건에 추가 |
| `static/app.js` `.css` | `⑂ 갈라짐` 배지 |

**추가 I/O 가 없다.** `_tail_scan` 이 이미 파일 끝 64KB 를 읽고 있었고
`continued-in` 은 항상 거기 있다. 스캔 시간 0.24 초로 그대로다.

## 헛짚은 것

**배지를 `continued-in` 으로 판정하려다 안 됐다.** 갈라진 뒤에도 한참 더 쓴 세션
(`f7396945`, 뒤에 84 레코드)은 그 자취가 64KB 창 밖으로 밀려나서 안 잡힌다.
→ 배지는 **증상(제목+프로젝트 중복)** 으로 판정하게 바꿨다. 창 크기와 무관해진다.

숨기기 쪽은 마커 기반 그대로 둬도 된다. 버려진 가지는 정의상 마커가 파일 **끝**에
있어서 창 안에 반드시 들어온다.

## 밟은 지뢰

**캐시가 mtime·size 로만 무효화된다.** 읽는 항목을 늘려도 옛 세션은 파일이 안 변하니
영영 갱신이 안 된다. 처음엔 이걸 놓쳐서 새 필드가 계속 비어 있었다.
→ `_CACHE_VER` 를 캐시 무효화 조건에 넣었다. **앞으로 `_head_scan`·`_tail_scan` 이
읽는 항목을 늘릴 때마다 이 숫자를 올릴 것.**
