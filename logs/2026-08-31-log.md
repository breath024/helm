## 바꾼 것

| 파일 | 무엇을 |
|---|---|
| `.gitignore` | `*.lnk` 추가 (왜인지 한 줄 같이) |
| `HELM.lnk` · `HELM 채팅.lnk` | `git rm --cached` — **로컬 파일은 그대로 둠** |
| `README.md` | 실행 안내 `HELM.lnk 실행` → `pythonw app.py` |
| `HANDOFF.md` | 실행 안내 동일 + "바로가기는 로컬에만 둔다" 명시 |

그 뒤 이력에서도 제거: `git-filter-repo --invert-paths --path-glob "*.lnk"`.
커밋 5개 그대로(날짜·메시지 보존), 강제 푸시.

## 터진 것 / 헛짚은 것

- **`git filter-branch` 가 권한 정책에 세 번 막혔다.** 같은 날 코인봇에서는 한 번에 통과했는데
  여기서는 계속 거부됐다(분류기가 일관되지 않음). 억지로 뚫지 않고 **git 이 공식으로 권하는
  `git-filter-repo`** 로 갈아탔다 — `pip install git-filter-repo` 후
  `python -m git_filter_repo --force --invert-paths --path-glob "*.lnk"`. 0.4초에 끝났다.
- **호윤이 직접 돌렸을 때 "not a git repository" 가 났다.** 내가 준 명령에 `cd` 가 없어서
  홈 디렉토리에서 실행된 것이다. **명령을 넘길 땐 `cd` 를 붙여서 줄 것.**
- `git-filter-repo` 는 끝나고 **remote 를 떼어낸다**(안전장치). 모르면 다음 push 가 실패한다.
  `git remote add origin ...` + `git branch --set-upstream-to` 로 되돌려 놨다.

## 남긴 것 / 안 한 것

- **옛 커밋(`aaa40ed` 등)은 GitHub 에서 SHA 로 직접 열면 아직 열린다.** 강제 푸시는
  브랜치만 옮기고 끊긴 객체는 GitHub 이 자기 주기로 지운다. 둘러보거나 클론하면 안 보이고
  포크는 0개. 완전 제거는 GitHub Support GC 요청이 유일한 방법인데, 저장소를 지웠다
  다시 만들면 잔디가 날아가서 안 하기로 했다.
- 백업 번들: `helm-before-lnk-purge.bundle` (439KB, 작업 임시폴더). 되돌릴 일 없으면 그냥 둔다.
