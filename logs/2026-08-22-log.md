## 무엇을 했나
호윤이 "Ctrl+V 같은 게 안 된다"고 해서 HELM 본체(`app.py`)에 클립보드 경로를 붙였다.
붙여넣기/복사 처리가 **아예 없던** 상태였다.

## 바꾼 것
| 파일 | 무엇을 |
|---|---|
| `app.py` | `import ctypes.wintypes` 추가 / `# 클립보드` 절 신설 — `_clip_open()`·`clipboard_get()`·`clipboard_set()`(ctypes, CF_UNICODETEXT) + `GET/POST /api/clipboard` |
| `static/app.js` | `# 클립보드` 절 신설 — `clipRead()`·`clipWrite()`·`termClipboardKeys(term)`. 패널 만들 때(WebGL 애드온 다음 줄) 부착 |
| `static/app.js` | 편집기(CodeMirror) `extraKeys`에 `Ctrl-V`/`Ctrl-C`/`Ctrl-X` 추가 |
| `HANDOFF.md` | 기능 목록에 "붙여넣기/복사" 항목 |

키 배치: **Ctrl+V · Ctrl+Shift+V · Shift+Insert = 붙여넣기 / Ctrl+Shift+C = 선택 복사.**
**Ctrl+C는 일부러 안 건드렸다** — Claude Code TUI에서 중단 신호로 써야 한다.

## 터진 것 / 헛짚은 것
- **진짜 원인.** xterm.js는 브라우저가 textarea에 쏘는 native paste에 얹혀 간다. 그런데
  pywebview(WebView2) 창 안에서는 클립보드 읽기가 권한 요청에 막혀 **조용히** 죽는다.
  그래서 "창에서만 안 되고 브라우저로 열면 되는" 모양이 나온다.
  → 브라우저 API를 먼저 써보고 실패하면 **서버가 윈도우 클립보드를 직접 읽어** 넘기게 했다.
  어차피 로컬에서 도는 앱이라 권한 벽이 없다.
- **ctypes 함정 두 개.**
  - `argtypes`를 안 주면 64비트 핸들이 int로 넘어가 `GlobalUnlock`에서 `OverflowError: int too long`. 첫 시도가 여기서 터졌다.
  - `SetClipboardData`에 넘긴 핸들은 **클립보드가 주인**이라 우리가 `GlobalFree` 하면 안 된다.
- **`OpenClipboard` 실패.** 다른 앱이 쥐고 있으면 잠깐 실패한다 → `_clip_open()`이 20ms 간격 8번 재시도.
- **헛짚은 것 하나.** curl로 POST 했더니 400 Bad Request가 떠서 라우트를 의심했는데,
  라우트가 아니라 **bash에서 한글이 깨져 JSON 파싱이 실패**한 것이었다. urllib으로 다시 쏘니 정상.
  (한글 윈도우 스크립트 인코딩 문제와 같은 뿌리)
